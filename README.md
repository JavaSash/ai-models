# AI Models

Исследовательский проект для изучения ИИ-агентов, многоагентных систем и автоматизации процессов разработки ПО и SMM.

Первый экспериментальный проект — Wimme.

## Текущий этап

Подготовка и ручная апробация инструкций агентов перед автоматизацией pipeline.

На данный момент доступен Analyst Agent — агент для преобразования бизнес-требований в формализованные спецификации задач.

## Структура проекта

```text
agents/
├── common.md
├── policies/
│   └── task-complexity.yaml
├── templates/
│   ├── agent-template.yaml
│   └── task-specification.yaml
└── roles/
    └── analyst.yaml
```

- `common.md` — общие инструкции для всех агентов.
- `policies/` — переиспользуемые правила и политики.
- `templates/` — шаблоны спецификаций агентов и выходных артефактов.
- `roles/` — специализированные инструкции агентов.

## Использование Analyst Agent

Для запуска агента передать ChatGPT или Codex следующий промпт, обеспечив доступ к репозиторию ai-models и целевому проекту.

```text
Act as Analyst Agent.

Follow instructions from:
- agents/common.md
- agents/roles/analyst.yaml

Project: JavaSash/wimmly

Task:
<task description>
```

Пути к инструкциям указаны относительно корня репозитория ai-models.

Аналитик самостоятельно загружает необходимые политики и шаблоны, изучает релевантный код проекта и формирует спецификацию задачи в YAML.

## Классификация задач

| Размер | Описание |
|---|---|
| S | Небольшое локальное изменение |
| M | Самостоятельная функциональность |
| L | Сложная или высокорисковая функциональность |
| XL | Требуется декомпозиция |

## Результат работы аналитика

Артефакт — `task_specification.yaml`.

Возможные статусы:

- `READY` — спецификация готова к передаче на следующий этап.
- `BLOCKED` — требуется уточнение человеком.
- `DECOMPOSITION_REQUIRED` — требуется декомпозиция задачи.

## Критерии оценки работы агента

При ручной апробации оценивать:

- Корректность понимания исходных требований.
- Корректность классификации сложности.
- Достаточность спецификации для реализации.
- Отсутствие избыточных требований и уточняющих вопросов.
- Соответствие существующей архитектуре проекта.
- Объём потребляемого контекста и токенов, если доступна статистика.

## Основные принципы

- От простого к сложному.
- Сначала ручная апробация, затем автоматизация.
- Минимально достаточный контекст.
- Минимальное вовлечение человека.
- Работа в рамках подписки ChatGPT Plus.
- Человеческий контроль над результатами.
