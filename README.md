# AI Models

Исследовательский проект для изучения ИИ-агентов, многоагентных систем и автоматизации процессов разработки ПО и SMM.

Первый экспериментальный проект — Wimme.

## Основные принципы

- От простого к сложному.
- Сначала ручная апробация, затем автоматизация pipeline.
- Чёткое разделение ответственности между агентами.
- Минимально достаточный контекст и расход токенов.
- Минимальное вовлечение человека.
- Работа в рамках подписки ChatGPT Plus.
- Человеческий контроль над результатами.

## Структура проекта

```text
ai-models/
└── agents/
    ├── policies/
    ├── templates/
    └── roles/
```

| Директория | Назначение |
|---|---|
| `/` | Документация проекта, план развития и инструкции по работе с репозиторием |
| `agents/` | Общие инструкции и конфигурация агентов |
| `agents/policies/` | Переиспользуемые правила и политики |
| `agents/templates/` | Шаблоны спецификаций агентов и выходных артефактов |
| `agents/roles/` | Специализированные инструкции и контракты отдельных ролей |

Подготовка и ручная апробация инструкций агентов перед автоматизацией pipeline.

| Агент | Спецификация | Апробация |

## Использование агентов

Для запуска агента передать ChatGPT или Codex соответствующий промпт, обеспечив доступ к репозиторию ai-models и целевому проекту.

Пути к инструкциям указаны относительно корня репозитория ai-models. Агент использует общие инструкции, спецификацию своей роли и необходимые политики и шаблоны. Дополнительный контекст загружается по необходимости.

## Analyst Agent

Агент отвечает за преобразование бизнес-требований в формализованные спецификации задач.

### Основные задачи

- Анализ требований и существующей реализации.
- Выявление переиспользуемой функциональности.
- Классификация и декомпозиция задач.
- Формирование функциональных требований и критериев приёмки.
- Выявление рисков, противоречий и зависимостей.
- Минимизация уточняющих вопросов человеку.

### Пример запуска

```text
Act as Analyst Agent.

Follow instructions from:
- agents/common.md
- agents/roles/analyst.yaml

Project: JavaSash/wimmly

Task:
<task description>
```

### Классификация задач

При классификации учитываются техническая сложность, объём реализации, риски и степень переиспользования существующих компонентов.

| Размер | Описание |
|---|---|
| S | Небольшое изменение или расширение существующей функциональности |
| M | Существенная новая функциональность или нетривиальные изменения бизнес-логики |
| L | Большой объём реализации, высокая техническая сложность или значительные риски |
| XL | Чрезмерный объём задачи, требующий декомпозиции |

### Результат работы

Артефакт — `task_<short_description>.yaml`.

| Статус | Описание |
|---|---|
| READY | Спецификация готова к передаче на следующий этап |
| BLOCKED | Требуется устранение блокирующих обстоятельств |
| DECOMPOSITION_REQUIRED | Требуется декомпозиция задачи |

### Критерии оценки

- Корректность понимания требований и классификации задачи.
- Достаточность спецификации для реализации.
- Соответствие существующей архитектуре проекта.
- Отсутствие избыточных требований и уточняющих вопросов.
- Объём потребляемого контекста и токенов, если доступна статистика.

## Tester Agent

Агент отвечает за проверку корректности реализации посредством автоматизированного тестирования.

### Основные задачи

- Анализ спецификации задачи, согласованной реализации и существующего тестового покрытия.
- Выбор необходимого уровня тестирования: Unit, Integration, E2E.
- Написание и актуализация автоматизированных тестов.
- Проверка критериев приёмки и регрессионных сценариев.
- Выявление дефектов реализации.
- Выполнение тестов и формирование отчёта.

Агент приступает к написанию тестов только после согласования реализации человеком. Изменение production-кода не входит в его полномочия.

### Пример запуска

```text
Act as Tester Agent.

Follow instructions from:
- agents/common.md
- agents/roles/tester.yaml

Project: JavaSash/wimmly

Task specification:
<path to task specification>

Implementation: approved.
```

### Результат работы

- Созданные или актуализированные автоматизированные тесты.
- Отчёт `test_report_<short_description>.yaml`.

| Статус | Описание |
|---|---|
| PASSED | Все обязательные проверки пройдены |
| FAILED | Обнаружены дефекты реализации |
| PARTIAL | Проверки выполнены частично |
| BLOCKED | Тестирование заблокировано |

### Критерии оценки

- Полнота покрытия требований и критериев приёмки.
- Корректность и читаемость тестового кода.
- Соблюдение существующих соглашений проекта.
- Переиспользование тестовой инфраструктуры.
- Отсутствие избыточных и дублирующих тестов.
- Способность выявлять дефекты реализации.
- Достоверность отчёта о тестировании.
- Минимизация расхода токенов и вовлечения человека.
